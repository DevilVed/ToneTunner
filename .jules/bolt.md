## 2025-02-23 - Short-circuiting in Max Search Loops Beats Hash Lookup Allocations
**Learning:** In max-element search algorithms like `Utils.getIndexOfLargest`, place `array[i] > largest` before expensive exclusion checks (e.g. `!indexesToAvoid.contains(i)`). Because `largest` monotonically increases, `array[i] > largest` only evaluates to true ~log N times out of N iterations. Converting `indexesToAvoid` to `HashSet` or allocating a `boolean[]` lookup table inside the search method introduces heavy object allocation/boxing overhead on every iteration, which actually degrades performance compared to short-circuited linear scans.
**Action:** Always verify short-circuiting conditions and measure object allocation costs before attempting hash table or boolean array optimizations inside hot loops.
