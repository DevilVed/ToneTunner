
## 2024-05-18 - [Eliminate Redundant Object Allocation in ONNX Inference Loop]
**Learning:** In highly repetitive loops, such as token generation in NLP models (`Whisper_decoder` ONNX model), repeatedly performing string concatenations (e.g., `"present." + i + ".decoder.key"`) and recreating container objects like `HashMap` inside the inference loop (`while (!(max == eos && max2 == eos))`) introduces severe garbage collection pressure and allocation overhead.
**Action:** When working with repetitive ONNX `Session.run(Map<String, OnnxTensor> input)` calls or similar high-frequency loops: 1) Pre-calculate and cache fixed string keys in `static final` structures instead of interpolating them inline. 2) Reuse container objects by calling `map.clear()` (and initializing with an appropriate capacity to avoid rehashing) rather than instantiating `new HashMap<>()` every iteration. This pattern demonstrated up to ~11.8x speedup in map setup alone, contributing significantly to lowering latency per generated token.
