## Configure your models

Open **Settings** on the main screen for everything in one place: AI providers and models, the local Whisper model, hands-free mode, the voice keyboard and voice input for other apps. **AI settings** also opens directly from the main screen and the voice keyboard. Its two sections are independent:

- **Transcription:** Groq, OpenAI, OpenRouter, an OpenAI-compatible HTTPS endpoint, or local Whisper. Cloud mode works without downloading ONNX models.
- **Enhancement:** optionally send the transcript to a separate Groq, OpenAI, OpenRouter, or compatible chat model. Cleanup instructions form part of its system prompt; transcript text is a separate user message. Leave **Use built-in cleanup rules** on for transcription editing, or turn it off to use your own system prompt. Enhancement is off until enabled. Text pieces and provider responses are bounded; in built-in mode, severe shortening of a sufficiently long piece returns the complete transcript without AI cleanup and displays a warning. Advanced custom prompts can deliberately request shorter output. Neither mode can guarantee that a model preserves meaning.

Enter preferred spellings under **Vocabulary and names to preserve**, separated by commas or lines. Vocabulary guides the enhancement model using the surrounding context; it does not automatically change ordinary words such as `will`, `may`, or `go` into names. For a predictable known correction, use **Word replacements**, one literal `heard text => preferred text` mapping per line, for example `tone tuner => ToneTunner`. Replacements run once before enhancement, also work when enhancement is off, and avoid changing a name inside a larger word. Explicit mappings are not rerun on their generated output. With enhancement off, vocabulary alone leaves recognized text unchanged.

Each cloud stage has its own provider, model ID, full endpoint URL, and API key. Built-in providers supply defaults; supported providers can refresh their model catalogs. Custom endpoints require a manually entered model ID. For custom services, use the full HTTPS transcription or chat-completion URL, including its path.

Keys are entered on the Android device, encrypted using Android Keystore, and stored outside Android backup. A blank key field preserves the saved key for that exact provider, stage, and endpoint; **Remove saved key** deletes it. No shared developer key is bundled. API usage is charged by the selected provider, separately from this free application.

Saved-key validation and credential decryption run off the settings UI thread. The settings screen can show whether an encrypted key file exists, but that status check does not decrypt or prove that the key is valid. Unsaved settings edits survive Activity rotation in memory; an Android process kill can discard unsaved edits. Typed API keys are excluded from saved Activity state, autofill and supported Android Content Capture. Keystore hardware backing varies by device, and a compromised app process can still access a key while it is being used.

Select the cloud-processing disclosure and save before cloud dictation is available. With no saved provider choice, transcription stays local. OpenRouter's ZDR option defaults on separately for both stages. Its transcription endpoint does not enforce per-request ZDR routing: Settings rejects that combination on Save, and the request guard also blocks upload unless you explicitly turn off the transcription ZDR requirement. Chat enhancement keeps its separate ZDR routing. **Upgrade note:** existing OpenRouter transcription users with ZDR enabled must choose another provider or explicitly disable only the transcription ZDR requirement before saving; this update does not silently weaken their privacy choice. Direct providers' retention settings must be managed in their own accounts; ToneTunner does not claim to change them.

For local transcription, select **Local Whisper** and use **Install local model**. The existing RTranslator Whisper-Small ONNX set remains supported. Local transcription with cloud enhancement still sends the resulting text to the enhancement provider.

## Dictate across Android

**Transcript history** on the main screen retains recognized text after successful delivery. Open a row to view or copy the final result or original recognition, or delete that text entry with confirmation. Recognition progress is saved before enhancement, and the final result is saved before delivery. If history storage fails, dictation still delivers its text with a warning and retains audio and recognized text under **Saved dictations** for recovery. Retry can save history once storage is available. Text history stays until deletion or uninstall; it is app-private and excluded from backup, but is not separately encrypted. Audio recovery has a separate lifetime. Returning to history refreshes the first page before loading further pages. In the voice keyboard, password fields remain blocked and local dictation in editors requesting no personalized learning skips permanent text history. Other entry points do not receive that editor flag. Android can reject very large clipboard transfers; the full stored text remains selectable without silent truncation.

Enable ToneTunner in Android's keyboard settings using **Enable voice keyboard** in the app, grant microphone permission, then select its voice keyboard in the intended text field. Tap the microphone to start and tap again to finish. Press-and-hold push-to-talk also works. You can switch back to your regular keyboard with the keyboard button.

Manual recording has **no 30-second cutoff** and stays active through thinking pauses. Audio is written to a private file with a fixed capture buffer. After you stop, it is transcribed sequentially in windows of at most 28 seconds and optionally enhanced in bounded text windows. Quiet boundaries are preferred; a hard cut carries 500 ms of audio context into the next window, with conservative text-overlap reconciliation. Audio staging does not grow with the complete recording; transcript text and model allocations still consume memory. Available storage, system microphone access, and provider quotas apply. The standalone recorder is manual. Automatic stop-on-silence is available in the voice keyboard and Android speech entry points. With keyboard automatic mode selected, focusing an eligible field can start capture without a new tap. **Automatic mode times out after 30 seconds without initial speech**; it has no fixed total-duration cap after speech begins. In noise, automatic recording may continue until manually stopped, subject to storage. The Android recognition service defaults to automatic mode; disable it in voice recognition settings to allow thinking pauses there too.

The display stays awake while foreground dictation records, transcribes, or enhances. Completion, errors, cancellation, or leaving the foreground release that policy. Leaving the app or hiding its voice keyboard cancels the active foreground operation. If a finished recording was already submitted, it was archived before processing and remains in Saved dictations for explicit retry or discard; live capture that has not been submitted is discarded when its foreground session ends.

The app also offers a standalone recorder, an Android `RecognitionService`, and a `RECOGNIZE_SPEECH` intent Activity. Integration with another keyboard's microphone depends on that keyboard; installing ToneTunner does not redirect every keyboard's voice service. A floating overlay is not included in this version.

Cancel stops pending work. A recording already submitted for processing remains in Saved dictations; cancelling live capture before submission discards that capture. Changing the active text field or keyboard invalidates pending insertion. Selection updates within the same editor do not destroy dictation. The voice keyboard blocks dictation in password fields and permits only fully local processing in editors requesting no personalized learning; standalone and speech-service requests do not receive those editor flags. There is no automatic fallback to another cloud provider or weaker privacy policy.

Open **Saved dictations** in the main app to preview/copy completed text, retry remaining audio, or discard a saved item. The list shows newest-first entries, count, and total audio size. There is no automatic age- or size-based pruning, so retained recordings use storage until you act on them. A failed request preserves earlier completed windows and the full audio. Retry is explicit, uses the current AI settings, and resumes at the saved window; the failed request may already have been billed. If enhancement fails, ToneTunner returns the complete transcript without AI cleanup, retaining deterministic spelling corrections and displaying a warning. A microphone read interruption ends capture and attempts to transcribe the captured prefix with a warning. A storage write/flush failure salvages the physically written, PCM16-aligned prefix with a partial-capture warning; bytes rejected by a failing/full filesystem cannot be recovered.

Legacy Android language codes and ISO three-letter aliases are normalized; three-letter-only tags such as `yue` and `haw` are retained. Provider/model language support still varies. In Auto mode, the first usable reported language is pinned for later windows. Some APIs return text without language metadata; choose an explicit language to avoid independent detection on those models. The near-silence filter checks RMS in 20 ms PCM frames and keeps a whole inference window if any frame exceeds the fixed threshold; it does not average energy over the whole window, amplify quiet audio, or reject arbitrary noise. Very quiet speech may still be skipped and room noise may still be recognized. An explicit retry can submit a quiet recording because retry bypasses the first-pass filter.

Translation to English is available with supported transcription models. ToneTunner checks support before cloud consent/key validation and microphone capture in the app and voice keyboard. Groq Whisper Turbo, OpenRouter, custom cloud routes, and the default OpenAI mini model are not supported translation routes; use Groq `whisper-large-v3`, OpenAI `whisper-1`, or local Whisper instead. Unsupported combinations report an error rather than silently transcribing the wrong task. Android's standard `RECOGNIZE_SPEECH` Activity always transcribes to honor the caller's speech-recognition contract.

## Data handling

Cloud transcription sends recorded audio to the chosen provider. Enhancement sends the transcript, cleanup instructions, and vocabulary to its provider; it does not read or upload screen contents, surrounding app text, or the clipboard. Local Whisper with enhancement disabled processes speech on the phone.

Finished recordings are moved into private no-backup recovery storage before processing, and completed-window progress is checkpointed there. **Processing failure, interruption, cancellation, or failed transcript-history persistence retains the audio and recognized text until explicit retry/discard; successful result delivery deletes that saved item when history was saved or history is disabled.** Both retained PCM and transcript metadata are plaintext inside app-private storage, not application-encrypted. Saved items consume storage until removed. If primary recovery storage is unavailable, a second private root and recognizable retained spool support later recovery; physical storage failure cannot guarantee persistence. Cancelling a live capture before submission deletes its temporary audio. Stale disposable spools are cleaned before a new capture; retained recovery audio is excluded from that sweep. API keys and dictated content are not written to diagnostic logs. Provider retention, usage metadata, account controls, connectivity, and charges remain governed by the provider. ZDR is a routing/retention policy, not a claim that cloud data never leaves the phone.

## Development and verification

The [full engineering record](docs/2026-10-20-voiceink-android-engineering-record.md) explains the architecture, alternatives, failure history, recovery behavior, and evidence limits. The [per-finding review response](docs/2026-10-21-detailed-review-response.md) records decisions for every DeepSeek review item. The [test inventory](docs/2026-10-20-verification-test-inventory.md) is the historical `bd0e80a` report inventory; later recovery and folder-review run results are described separately in the engineering record. The [clean-clone build recipe](docs/build-recipe.md) documents native preparation and the F-Droid/network-isolation limits.

Build on GitHub Actions; no local Android SDK is required. The current workflow runs JVM/lint checks, then API 28, API 34, API 35 with 16 KB pages, and API 36 emulator tests, and gates APK packaging on successful verification. Reports are uploaded even if verification fails. The new cleanup/history regression checkpoint ran 272 JVM tests with 15 expected failures before implementation; its final integrated verification is recorded in the new engineering study. Development uses Gradle 8.14.5 and JDK 17 in CI.

The [native dependency build](tools/native/README.md) rebuilds ONNX Runtime Extensions' JNI libraries from pinned upstream source with 16 KB linker alignment. Its published Android AAR still contains unaligned libraries. The build preserves the official Java classes, records provenance, and includes the upstream MIT license. Final APKs receive ELF and ZIP alignment checks. The ELF checker inspects 64-bit LOAD segments; ZIP alignment and ABI-presence checks cover packaged payload placement, not 32-bit ELF LOAD alignment or physical ARM execution. Caller-supplied source/AAR paths avoid the wrapper's Git/Maven fetches, but upstream CMake dependencies may still fetch unless separately prepared. A fully network-isolated build, `fdroid lint`, and an isolated F-Droid server build have not been verified, so F-Droid readiness is not established.

Tests exercise request construction, privacy filters, provider failures, cancellation, malformed/truncated results, credential configuration, editor eligibility, audio ownership, and long recording segmentation. The [long-recording design and reference implementations](docs/superpowers/specs/2026-10-20-cloud-dictation.md#long-recording-requirement-user-update) explain the file spool and bounded inference algorithm. Physical-device microphone/keyboard testing and real-provider transcription quality testing are separate from automated verification.
